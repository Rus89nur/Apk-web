# Полный QA АПК_ГИ (тестеровщик)

Сценарийный прогон веб-PWA как живой пользователь, не «нажми все кнопки подряд». Иначе застрянешь на file picker / confirm wipe.

## Когда

Только по явному запросу: «тестеровщик», «полный QA», «прокликай», «как пользователь», «пройди всё приложение», «полный тест программы», или при запуске субагента `testerovshchik`.

Не после каждой фичи. Не замена `verifier`. Verifier сверяет diff; этот скилл — полный продукт кликами. Конвейер planner→implementer→verifier не заменяй и сам в него не встраивайся.

## Среда

1. Если нет сервера — `python3 dev-server.py` → http://localhost:3000/ (не `file://`). Порт 3000, Cache-Control no-store.
2. Браузер: MCP `cursor-ide-browser`. Порядок: tabs list → navigate → lock → snapshot → click/type/fill → snapshot. Один скриншот ≠ проверка. Не CDP `Input.*`. Консоль: `Runtime.evaluate` / Log, не Input.
3. После работы — unlock.
4. Десктоп (сайдбар `.nav-item`) и узкий viewport ~390px (`.bottom-nav-item`). Phone MQ: `max-width: 900px`.
5. `npm test` — не твоя задача (это `apk-web-verify` / verifier). Можно глянуть, но отчёт строится по UI.

Перед прогоном прочитай `QA_WEB.md` и `MOBILE_PHONE_MODE.md` §8 — это чеклист, не выдумывай свой.

Код, CSS, HTML, sw.js, тесты, git — НЕ трогай. Коммиты не делай. Кэш не bump.

## Карта экранов

Навигация: `.nav-item` / `.bottom-nav-item` с `data-screen`. Вложенные — плитки Настроек / `data-go` на главной, не пункты бара.

| Экран | Как открыть | Что прокликать |
| --- | --- | --- |
| home | `data-screen=home` | Часы, полоса графика, «Создать полный акт», «Справка по ПБ», сокращённый акт, статистика, «Сборка: web-N». Если баннер «данных нет» — Восстановить (пикер); не wipe IDB. |
| wizard | `data-screen=wizard` или `data-go=wizard` | 6 шагов: Дата и комиссия → Организация → Объект → Нарушения → Выводы → Генерация. Назад/Далее, сводка (свёрнута), черновик. Нарушение: добавить, модалка `#wizardModalRoot`, textarea, закрытие ×/Отмена. Свои тестовые данные. |
| spravka | Главная `data-go=spravka` (в баре нет) | 7 шагов: Дата → Объекты → Субподрядчики → Работники → Нарушения → РММ → Генерация. Сводка, Word на последнем шаге. |
| history | `data-screen=history` | Поиск `#historySearch`, pills, сортировка, открыть свой акт, × своего тестового в корзину. |
| reports | `data-screen=reports` | Фильтры, донат, подрядчики, виды, просрочка, график, «Скачать отчёт», Excel графика. Зафиксировать: скачалось / ошибка / молчание. |
| elimination | `data-screen=elimination` | Карточки, срок/просрочка, отметка, bulk если есть. Не ломай чужие акты. |
| settings | `data-screen=settings` | Плитки: шаблоны акта/справки, мастер шаблонов; комиссия, орг., объекты, реестр нарушений, виды, представители, график; бэкап, корзина. ML — ожидаемо «Только iOS (архив)». «Обновить приложение» не жать без запроса. |
| trash | плитка Корзина | Восстановить СВОЙ тестовый акт. |
| violations | Настройки → Нарушения | Поиск, фильтр вида, добавить (без порчи реестра — отмена), Excel. |
| violation-types | Настройки → Виды нарушений | Список открывается, без миграции «на всех». |
| Модалки | по ходу | × / Отмена / оверлей; скролл не зависает. |

Демо-бэкап: `assets/sample-demo.gazprombackup`. Импорт replace И merge — только если file input доступен агенту. Иначе «не проверено», без костылей. Не делай clear IDB перед импортом.

## Запреты

- Не менять HTML/CSS/JS/sw.js/тесты, не bump cache, не git commit/push.
- Не «Очистить данные», не clear IndexedDB, не wipe. IDB не в git — не чистить даже «для чистоты прогона».
- Не удалять акты, которые не создал в этой сессии. Только свой тестовый акт — в корзину, чтобы проверить восстановление.
- Не утверждать «работает» без клика и видимого результата.
- За 4 неудачи на шаге — стоп по шагу, блокер, дальше.
- SW на localhost отключён — офлайн/PWA install не проверять на localhost (пометить «не проверено»; Pages только если пользователь явно сказал).
- Камера, системный file picker, печать, установка PWA — если недоступны, в «Не проверено».

## Маршрут (порядок, экраны не пропускать)

1. Главная
2. Полный акт 6 шагов (черновик, по возможности завершение)
3. Справка по шагам
4. История
5. Отчёты
6. Устранение
7. Настройки и справочники
8. Импорт демо, если пикер есть
9. Корзина (свой акт)
10. Модалки
11. Затем ~390px: бар из 6 пунктов, мастер Назад/Далее не под баром

## Формат отчёта (строго)

## Сводка

OK / ЧАСТИЧНО / СЛОМАНО (одна строка)

## Пройдено

таблица: сценарий | ок/баг/не проверено | кратко

## Баги

для каждого: экран, шаги воспроизведения, ожидалось, факт, консоль если есть

## Не проверено

причина (пикер файлов, SW, PWA install, камера…)

## Консоль

ошибки за сессию

Вердикт не смягчай: если мастер не завершается — это СЛОМАНО, не «почти ок».

Известные ограничения (не баги, если так и задумано): SW off на localhost; ML только iOS; номер акта уникален в рамках года.
